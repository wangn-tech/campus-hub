# 前端接口清单

## 1. 文档目的

本文汇总当前前端实际调用的 HTTP 接口和 WebSocket 事件，作为新后端接口设计、兼容层和重构排期的依据。

接口来源：

- `frontend/src/api/activity/router.ts`；
- `frontend/src/api/home/router.ts`；
- `frontend/src/api/message/router.ts`；
- `frontend/src/api/profile/router.ts`；
- `frontend/src/api/publish/router.ts`；
- `frontend/src/api/register/router.ts`；
- `frontend/src/api/tags/router.ts`；
- `frontend/src/api/ticket/router.ts`；
- `frontend/src/utils/http.ts`；
- `frontend/src/utils/websocket.ts`。

## 2. 前端请求约定

### 2.1 Base URL

前端默认 Base URL：

```text
http://8.136.112.63:3030
```

H5 环境可使用相对路径，非 H5 环境会拼接 Base URL。

### 2.2 请求头

登录后，前端从本地存储读取 `accessToken`，并添加：

```text
Authorization: Bearer <accessToken>
Content-Type: application/json
X-Client-Info: <客户端信息>
```

文件上传使用 `multipart/form-data`。

### 2.3 响应约定

前端按业务码判断成功或失败：

- `code = 0`：成功；
- `code != 0`：业务失败；
- Token 相关错误会尝试刷新或跳转登录页。

## 4. WebSocket 事件清单

### 4.1 连接配置

前端默认连接地址：

```text
ws://192.168.10.9/ws
```

连接成功后，客户端首先发送认证消息，认证通过后才执行业务消息投递。

### 4.2 客户端发送事件

| 事件类型 | Data | 说明 |
|---|---|---|
| `auth` | `token` | WebSocket 登录认证 |
| `ping` | 无 | 心跳检测 |
| `send_message` | `group_id`、`msg_type`、`content` 或 `image_url` | 发送群消息 |
| `mark_read` | `group_id`、`message_id` | 标记群消息已读 |

### 4.3 服务端发送事件

| 事件类型 | Data | 说明 |
|---|---|---|
| `auth_success` | 用户信息 | 认证成功 |
| `auth_failed` | 错误信息 | 认证失败 |
| `pong` | 无 | 心跳响应 |
| `ack` | 客户端消息 ID、服务端消息 ID | 消息确认 |
| `new_message` | 消息内容 | 新群消息 |
| `notification` | 通知内容 | 系统通知 |
| `verify_progress` | 学生认证进度 | 学生认证进度更新 |
| `error` | 错误码、错误信息 | 服务端错误 |

前端页面还监听以下名称：

- `newMessage`；
- `notification`；
- `verifyProgress`；
- `studentAuthUpdate`。

其中部分命名与 WebSocket 原始事件类型存在下划线和小驼峰不一致，新系统应统一事件命名并在文档中固定。

## 5. 当前接口问题汇总

1. 活动、通知、聊天接口的版本前缀不统一。
2. 活动列表同时存在 `/list` 和 `/lists`。
3. 活动标签和兴趣标签分别走不同路径。
4. 部分接口要求前端传 `user_id`，新系统应优先从 Token 获取当前用户 ID。
5. QQ 邮箱验证码接口在不同前端模块中存在 GET 和 POST 混用。
6. 文件上传和业务提交耦合，新系统建议先上传文件，再提交业务 ID。
7. WebSocket 事件命名存在下划线和小驼峰不一致。
8. 部分接口路径以名词单复数区分不同含义，语义不清晰。

## 6. 新系统接口收敛原则

- 统一前缀：`/api/v1`；
- 资源命名使用复数名词；
- 当前用户统一使用 `/users/me`；
- 活动搜索统一走 `/activities/search`；
- 标签统一走 `/tags`，通过 `type` 区分活动标签和兴趣标签；
- 通知、群聊、消息全部纳入版本前缀；
- 文件上传独立为 `/files/images`；
- 核销独立为 `/check-ins`；
- WebSocket 路径可保留 `/ws`，消息事件使用统一命名；
- 迁移期如需兼容前端旧路径，可在路由层做临时映射，并标注删除时间。
