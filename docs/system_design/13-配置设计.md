# 配置设计

## 1. 文档目的

本文定义 CampusHub 后端基于 Viper 的配置加载方式、配置结构、环境变量、多环境策略、敏感信息处理和配置项清单。

## 2. 配置管理原则

1. 使用 Viper 加载配置。
2. 默认配置使用 YAML 文件。
3. 环境变量可以覆盖文件配置。
4. 生产环境敏感信息不写入仓库。
5. 服务启动时校验必要配置。
6. 配置结构在代码中使用强类型结构体表达。
7. 本地、测试、生产环境配置分离。

## 3. 配置加载顺序

优先级从低到高：

1. 代码内默认值；
2. `configs/config.dev.yaml` 等环境配置文件；
3. 环境变量；
4. 启动参数，如需要。

高优先级配置覆盖低优先级配置。

## 4. 配置文件规划

```text
configs/
├── config.dev.yaml
├── config.test.yaml
└── config.prod.yaml
```

本地开发使用 `config.dev.yaml`。生产环境只提交非敏感模板，真实值通过环境变量或密钥管理系统注入。

## 5. 环境变量规则

统一前缀：

```text
CAMPUSHUB_
```

嵌套配置使用下划线映射，例如：

| 配置路径 | 环境变量 |
|---|---|
| `mysql.host` | `CAMPUSHUB_MYSQL_HOST` |
| `mysql.port` | `CAMPUSHUB_MYSQL_PORT` |
| `redis.password` | `CAMPUSHUB_REDIS_PASSWORD` |
| `jwt.access_secret` | `CAMPUSHUB_JWT_ACCESS_SECRET` |
| `elasticsearch.addresses` | `CAMPUSHUB_ELASTICSEARCH_ADDRESSES` |

数组类型环境变量使用逗号分隔，例如：

```text
CAMPUSHUB_ELASTICSEARCH_ADDRESSES=http://es:9200
```

## 6. 配置结构

配置按以下部分组织：

- `app`；
- `http`；
- `mysql`；
- `redis`；
- `kafka`；
- `elasticsearch`；
- `websocket`；
- `storage`；
- `jwt`；
- `captcha`；
- `email`；
- `log`；
- `observability`；
- `feature`。

## 9. 配置校验

启动时必须校验：

- MySQL 地址、账号和数据库名；
- Redis 地址；
- Kafka Brokers；
- Elasticsearch 地址；
- JWT 密钥和有效期；
- 对象存储 Bucket；
- 生产环境不能使用默认密钥；
- 生产环境 CORS 不能长期使用 `*`。

校验失败应快速失败并输出明确错误。

## 10. 敏感信息管理

敏感配置包括：

- 数据库密码；
- Redis 密码；
- Kafka SASL 凭证；
- JWT 密钥；
- 对象存储密钥；
- 邮箱 SMTP 密码；
- OCR AccessKey；
- 短信或第三方服务密钥。

处理原则：

- 不提交真实生产值；
- 使用环境变量或密钥管理系统；
- 日志中不打印密钥；
- 错误信息不返回完整连接串；
- 配置模板可提交，真实配置不提交。

## 11. 配置变更规则

1. 新增配置必须提供默认值或标注必填。
2. 删除配置前确认所有环境已完成切换。
3. 配置结构变化必须更新本文档。
4. 配置项命名保持小写和下划线风格。
5. 不同环境的差异必须显式记录。
