# 安全设计

## 1. 文档目的

本文定义 CampusHub 的认证、授权、密码、Token、接口防护、文件安全、敏感数据保护、审计和 WebSocket 安全要求。

## 2. 安全原则

1. 默认不信任客户端请求。
2. 所有权限在服务端校验。
3. 最小权限访问。
4. 敏感数据最小化采集、展示和保留。
5. 安全失败并记录审计。
6. 不依赖前端隐藏按钮实现权限控制。
7. 所有安全策略应可测试、可追踪。

## 3. 认证设计

### 3.1 注册与登录

- 使用邮箱和密码注册；
- 注册可要求邮箱验证码；
- 登录可要求图形验证码；
- 登录失败次数受限；
- 登录成功后签发 Access Token 和 Refresh Token；
- 记录最后登录时间。

### 3.2 Access Token

- 使用 JWT；
- Access Token 短期有效；
- 包含用户 ID、Token ID、签发者、过期时间；
- 不放入密码、权限快照等不必要敏感信息；
- 通过 Authorization Header 传递。

### 3.3 Refresh Token

- Refresh Token 应长期有效但可撤销；
- 服务端保存 Token ID、用户 ID、设备信息和过期时间；
- 刷新时轮换 Refresh Token；
- 异常使用时撤销该用户相关令牌。

### 3.4 Token 撤销

以下场景需要撤销 Token：

- 用户退出登录；
- 修改密码；
- 账号注销；
- 检测到令牌异常；
- 管理员禁用用户。

Access Token 可通过 Redis 黑名单撤销，黑名单 TTL 与 Token 剩余有效期一致。

## 4. 授权设计

### 4.1 RBAC

基础角色：

- 普通用户；
- 管理员。

活动上下文中的角色：

- 活动组织者；
- 活动群成员；
- 报名者。

### 4.2 权限校验位置

- 路由中间件完成是否登录校验；
- Service 层完成资源归属和业务权限校验；
- 数据查询必须附带权限条件；
- WebSocket 消息发送前校验群成员关系。

### 4.3 典型授权规则

| 操作 | 授权规则 |
|---|---|
| 编辑活动 | 活动组织者或管理员 |
| 取消活动 | 活动组织者或管理员 |
| 查看报名列表 | 活动组织者或管理员 |
| 核销票据 | 活动组织者或管理员 |
| 查看票据详情 | 持票人、活动组织者或管理员 |
| 查看群消息 | 群成员 |
| 发送群消息 | 群成员且群状态正常 |
| 查看信用流水 | 用户本人或管理员 |
| 审核活动 | 管理员 |
| 管理用户 | 管理员 |

## 5. 密码安全

- 密码必须经过哈希存储；
- 推荐使用 bcrypt，也可评估 argon2id；
- 不记录明文密码；
- 不在日志或错误信息中返回密码；
- 修改密码需要验证原密码；
- 忘记密码通过邮箱验证码重置；
- 密码长度和复杂度由 DTO 校验。

## 6. 接口防护

### 6.1 限流

需要限流的接口：

- 登录；
- 注册；
- 发送邮箱验证码；
- 图形验证码校验；
- 文件上传；
- WebSocket 消息发送；
- 票据核销。

限流可基于：

- IP；
- 用户 ID；
- 邮箱；
- 接口路径。

### 6.2 参数校验

- 使用 Validator 做结构和格式校验；
- 字符串限制最大长度；
- 枚举只接受白名单值；
- 分页大小设置上限；
- 经纬度范围校验；
- 文件类型和大小校验。

### 6.3 CORS

- 开发环境可使用本地来源；
- 生产环境明确配置允许 Origin；
- 不建议生产环境长期使用 `*`；
- WebSocket 单独校验 Origin。

### 6.4 防重放与幂等

关键接口使用唯一请求 ID：

- 报名；
- 核销；
- 文件确认；
- 通知已读。

服务端通过唯一索引或去重表防止重复处理。

## 7. 文件上传安全

### 7.1 允许类型

图片上传应限制为：

- JPEG；
- PNG；
- WebP；
- GIF，如业务需要。

学生证、头像、活动封面应使用不同业务类型和访问策略。

### 7.2 安全检查

- 校验 MIME 和扩展名；
- 校验文件大小；
- 对图片进行重新编码或元数据清理，可选；
- 文件路径不可由客户端直接控制；
- 文件访问 URL 使用随机对象名；
- 隔离未审核文件；
- 防止可执行文件伪装上传。

### 7.3 学生证图片

- 仅限认证审核相关人员访问；
- 不进入公开搜索索引；
- 认证完成后按保留期限处理；
- 访问行为应记录审计。

## 8. 敏感数据保护

### 8.1 敏感字段

包括：

- 密码；
- 真实姓名；
- 学号；
- 学生证图片；
- 联系电话；
- 邮箱；
- Token；
- 第三方服务密钥。

### 8.2 存储策略

- 密码只保存哈希；
- 学号和真实姓名加密存储；
- 学号同时保存哈希值用于唯一约束；
- 生产密钥通过环境变量或密钥管理系统注入；
- 列表接口默认不返回敏感字段。

### 8.3 展示策略

- 公开主页不展示学号和认证详情；
- 普通用户不能查看他人报名明细；
- 管理接口展示敏感信息时按需脱敏；
- 日志中对邮箱、手机号等字段脱敏。

## 9. WebSocket 安全

- 校验 Origin；
- 连接后必须在限定时间内认证；
- 未认证连接不能订阅房间；
- 发送消息前校验群成员身份；
- 限制单用户连接数；
- 限制消息频率和消息大小；
- 不接受未登记的图片 URL；
- 服务停机时通知客户端重连。

## 10. 数据库安全

- 使用 GORM 参数绑定，避免 SQL 注入；
- 不拼接未处理的排序字段，排序字段使用白名单；
- 数据库账号最小权限；
- 生产环境不使用 root 账号连接应用；
- 软删除和归档结合，避免数据长期泄露；
- 定期备份并验证恢复流程。

## 11. XSS 与内容安全

- 活动描述等富文本内容应过滤危险标签和脚本；
- 前端渲染富文本应使用安全渲染策略；
- 消息内容不应直接注入 HTML；
- 文件 URL 仅允许可信存储域名。

## 12. 审计日志

需要记录：

- 登录成功和失败；
- 密码修改；
- 账号注销；
- 活动创建、审核、取消；
- 票据核销；
- 学生认证审核；
- 管理员操作；
- 异常访问和限流命中。

审计字段：

- 操作人；
- 操作类型；
- 资源类型和资源 ID；
- IP；
- User-Agent；
- 操作结果；
- Trace ID；
- 操作时间。

## 13. 传输安全

- 生产环境使用 HTTPS；
- WebSocket 生产环境使用 WSS；
- 敏感接口不通过明文 HTTP 传输；
- 反向代理设置安全响应头，具体按部署规范执行。

## 14. 安全测试

上线前至少覆盖：

- 未登录访问受保护接口；
- 普通用户访问管理员接口；
- 用户访问他人私有资源；
- 重复报名和重复核销；
- 非法文件上传；
- 异常 Token 和过期 Token；
- WebSocket 未认证发消息；
- SQL 注入和 XSS 基础测试；
- 限流和验证码绕过测试。

## 15. 安全约束

1. 生产环境不得使用默认 JWT 密钥。
2. 生产环境不得跳过密码哈希。
3. 不得在错误响应中泄露堆栈、连接串或密钥。
4. 不得让前端直接访问中间件管理端口。
5. 所有管理操作必须有审计记录。
6. 敏感数据导出必须经过授权。
